# خطة العمل الهندسية — SO-101 Studio V4

## المرحلة الأولى: ما أُنجز
- تأسيس تطبيق سطح مكتب CustomTkinter مع مشغلي Windows وLinux/Raspberry Pi وبيئة افتراضية.
- بناء تبويبات العتاد والمعايرة، التسجيل، التدريب/الحزمة السحابية، وRollout.
- فصل السجل وإدارة البيئة واكتشاف العتاد وبناء العمليات واستيراد النماذج ضمن `core/`.
- دعم LeRobot CLI الحديث لـSO-101، وتسجيل dataset متعدد الكاميرات مع وصف مهمة.
- تدريب ACT مع TF32 ومنع AMP، وإيقاف طارئ للعمليات التي أطلقها التطبيق.
- تصدير datasets واستيراد وفحص checkpoints.
- بعد تدقيق Iteration 2 التمهيدي: تصحيح البحث المتداخل للمعايرة، تحديثات Tk من الخيوط الخلفية، مدخلات الأرقام، حماية المعاينة، وإصلاح متطلبات OpenCV وتشغيل الطرفية.

## الوضع الحالي
- تطبيق V4 قابل للاستيراد وتشغيل واجهته، مع بناء أوامر LeRobot v0.7.0+ واختبارات الوحدات.
- عمليات hardware I/O لا يمكن اعتمادها نهائياً دون تجربة على الذراعين والكاميرتين الفعليتين.
- Dry-Run يتحقق من تركيب الأوامر فقط، وليس من نجاح المعايرة المادية أو حركة الروبوت.
- تبقى معايرة البرمجيات/الإصدارات وتوافق PyTorch/CUDA حسب الجهاز مسؤولية التثبيت؛ المكونات الثقيلة غير مثبتة من `requirements_gui.txt`.

## Iteration 2 — أولويات التطوير

### 1. تثبيت الجودة والتحقق المادي
- تشغيل الاختبارات في CI على Windows وLinux مع بيئات Python مدعومة.
- اختبار تركيب أوامر كل CLI ضد `--help` لنسخة LeRobot المثبتة، لمنع اختلاف أسماء الوسائط مستقبلاً.
- اختبار عملي موثق: كل ذراع منفرداً، IDs السيرفو، الكاميرات، تسجيل حلقة، تدريب قصير، ثم rollout آمن.
- تحسين رسائل الخطأ وإظهار سجل subprocess وحالته داخل الواجهة.
- إغلاق التطبيق مع إيقاف العمليات والكاميرات وإزالة callbacks بطريقة آمنة.

### 2. تجربة الطلاب
- معالج إعداد أول تشغيل يكتشف المنافذ والكاميرات ويقترح الإعدادات دون افتراض COM ثابت.
- واجهة عربية/إنجليزية قابلة للتبديل، مع تعليمات مبسطة وصور/فيديو قصير ومصطلحات موحدة.
- وضع تدريب آمن: محاكاة/فحص أوامر قبل تحريك العتاد، تأكيدات قبل التسجيل وRollout، زر إيقاف واضح، وشرح مخاطر التغذية والطاقة.
- عرض تقدم الحلقات والتسجيل والتدريب، التحقق من وصف المهمة وعدد الحلقات ومساحة القرص قبل البدء.
- استيراد/تصدير ملفات إعدادات وإظهار أخطاء المنافذ والكاميرات مع خطوات إصلاح موجزة.

### 3. موثوقية التسجيل والتدريب والنشر
- إضافة إدارة مهام subprocess موحدة مع إلغاء آمن، حالات وأكواد خروج، وتدوير السجلات.
- التحقق من dataset قبل التدريب: metadata، fps، أسماء الكاميرات، عدد الحلقات، واكتمال ملفات البيانات.
- التحقق من checkpoint وخصائصه (نوع السياسة، شكل الصور، أسماء المفاصل) قبل rollout.
- جعل إعدادات GPU/CPU وذاكرة VRAM وتوصيات batch size واضحة، وعدم فرض CUDA على Raspberry Pi.
- تنظيم حفظ الإعدادات والنماذج والبيانات مع نسخ احتياطي وتفادي الكتابة فوق ملفات موجودة دون موافقة.

### 4. ذراع Leader مستقبلي: ESP32-C3 SuperMini + AS5600
- تحديد مواصفات العتاد أولاً: عدد المحاور، نطاق كل محور، اتجاه الدوران، جهد التغذية، وتوصيل I2C/المغناطيس لكل AS5600.
- بناء نموذج firmware يقرأ الحساسات مع معايرة الصفر، التفاف الزاوية، حدود آمنة، كشف فقد الحساس، ومعدل أخذ عينات ثابت.
- اختيار قناة الاتصال والتعريف البرمجي (USB Serial كبداية، مع بروتوكول بإصدار ورسائل محددة، checksum ومهلة/heartbeat).
- تصميم طبقة Teleoperator قابلة للتبديل في V4؛ عدم تمثيل ESP32 كـ`so101_leader` قبل وجود driver/adapter فعلي متوافق مع LeRobot.
- بناء مكيّف يحول زوايا AS5600 إلى المفاصل/المجالات المتوقعة للـSO-101 مع اتجاهات وحدود وتحجيم ومعايرة محفوظة.
- إضافة محاكاة واختبارات بروتوكول، ثم اختبار محور واحد، ثم دمج تدريجي على كل المحاور قبل السماح بالتسجيل أو قيادة follower.
- وضع زر إيقاف/heartbeat timeout وسلوك آمن عند انقطاع USB أو قراءة غير منطقية؛ وتوثيق السلامة الكهربائية والميكانيكية.

## ترتيب التنفيذ المقترح
1. إكمال التحقق النهائي لـIteration 2 الحالي وتثبيت نتائج الاختبارات.
2. معالجة أول تجربة فعلية على العتاد وإغلاق أي خلل يظهر.
3. إضافة دليل/معالج إعداد الطالب والتحقق المسبق قبل التسجيل وRollout.
4. تحسين إدارة العمليات وحالة التسجيل والتدريب.
5. تصميم مواصفات Leader ESP32-C3/AS5600 واختبار firmware مستقل، ثم بناء adapter تجريبي.
6. الدمج على مراحل مع اختبارات أمان قبل الاستخدام التعليمي.
